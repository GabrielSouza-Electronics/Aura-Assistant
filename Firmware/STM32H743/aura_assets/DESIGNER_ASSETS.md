# UI assets owned by TouchGFX

All static UI pixel data is generated by TouchGFX from `TouchGFX/assets/images`.
Migrated startup, Settings, Calendar, Tasks and gesture hints: `aura/managed`.

Change Layout Rotation, format, dithering and supported compression in the
Designer Images tab, then **Generate Code** and rebuild Debug. Widgets now
render Bitmap IDs through Image, honoring generated conversion settings.
L8 requires at most 256 RGBA colors. The migration selects lossless L8 when
possible, otherwise ARGB8888. Keep alpha for transparent sprites. No rotation
settings are written by the migration tool.

The migrated `aura/managed` PNGs use the same orientation convention as the
existing project: source PNG pre-rotated 90 degrees left and Designer Layout
Rotation 90. Configure that rotation in Designer, not in generator JSON edits.
Legacy pixel arrays must be reconstructed with their logical row stride
before rotating; widget dimensions alone cannot describe raw pixel order.

`aura_assets/compiled` contains only bitmap ID tables and layout/font metrics,
not duplicate pixel arrays. Artwork generators stay outside TouchGFX. Legacy
generators finish by running `gen/migrate_designer_assets.py`, exporting PNGs
and replacing temporary raw arrays with ID tables. Generate Code afterward.

The Tasks progress ring remains dynamically drawn in RAM, not a static asset.
Audio WAV/C arrays are independent of Designer image conversion.

The current physical 300x260 Chat avatar is in `aura/avatar300`, one directory
per clip. All 163 PNGs are pre-rotated left (file size 260x300). Existing 124
frames retain their Designer settings; 39 Speak frames are imported separately
and reserved in avatarSpeakIds. All Speak frames use a 6 pixel physical right
offset (framebuffer Y=84); Screen1View identifies them by explicit bitmap IDs.
Speak is not part of AvatarAnimation::Count or
its scheduler; the speaking flag still uses Idle until behavior is specified.
Before enabling Speak, set its Layout Rotation to 90 in Designer, then Generate
Code and rebuild. The installer never changes Layout Rotation.

All clips use 10 fps. Idle and specials play forward then backward without
duplicating the last frame; Blink plays forward. Opening Chat keeps the avatar
hidden for 1000 ms to let the screen load, then fades Idle in over 2000 ms.
Idle repeats until the fade completes and its current cycle ends, then plays
Goodbye as Hello, followed by Smile. Closing waits for the current
clip and completes Goodbye before leaving. The avatar is positioned at physical
(90,120), framebuffer (120,90). Its bottom stays at physical Y=380 despite the
40 pixel reduction in image height.
The existing divider is extended to 420 pixels using overlapping copies and
aligned with the image cut at physical Y=380.
The ring experiment was cancelled: its widgets, generators and PNGs were removed.
Only the divider light and its spark remain below the avatar, fading with it;
background particles retain their default routes. The light reuses existing
Designer bitmaps and needs no additional framebuffer or QSPI assets.

Normal selection occurs only after a full Idle cycle: Blink 45%,
the four looks together 30%, Thinking 3%, continue Idle 22%. Smile plays only
after the opening Goodbye greeting. Smile and Coffee render 2 pixels to physical
screen right (framebuffer Y=88 instead of 90); Thinking renders 4 pixels to the
right (Y=86), in all contexts, without changing source PNGs. Coffee becomes
eligible after 60 seconds, takes priority at an Idle boundary, then uses a
random 60-75 second interval. Specials always return to Idle in normal mode.

Task-context APIs `APP_Avatar_SetPreparing(bool)` and
`APP_Avatar_SetSpeaking(bool)` publish two independent flags through Model /
Presenter. Preparation loops Thinking, Idle, Blink, Idle. Speaking has
priority and uses Idle until speech animation assets exist. Microphone/ToF
owners must publish the flags; no unconfirmed detection rules are installed.
